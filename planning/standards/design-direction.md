# 视觉设计方向（Design Direction）

> **用途**：本文把 Colophon 从「一堆待审查的视觉提议」收敛成**一个最优设计方向**——在「简洁」基线上，叠加一组**有出处、克制的小特色**，使它既简洁又有辨识度，且与 iA Writer / Bear / MiaoYan 等竞品拉开距离。它是 mockup 的定调依据，也是 [ui-and-design.md](./ui-and-design.md) 中「留到实现时再定」条目（默认字体、强调色色值、排版数值、品牌记忆点）的落地答案。
>
> **上位文档**：[PRD.md](../PRD.md)（§3 定位、§4 差异化、§5 功能、§7 技术）、[ui-and-design.md](./ui-and-design.md)（硬约束）。凡冲突以 PRD / ui-and-design 为准。
>
> **出处纪律**：本文每一条特色都标注来源——要么是我们调研过的产品（见 `docs/`、签名细节素材库），要么是可信设计文献（iA、Butterick、Rams、Apple、Anthropic Frontend Design skill、Rauno Sirén 等）。**禁止凭空**。文中引用「对抗式审查第 N 条」指本轮那份重合审查。
>
> **语言约定**：本文用中文；搬进真实仓库时所有代码/API/色值/字体名/快捷键保持英文。

## 1. 自我审查结论（哪里对、哪里太 generic、与谁重合）

诚实地讲，当前提议方向**每一件单品都对，但组合起来是三家的拼贴**——这是最该毒舌的地方（对抗式审查第 8 条）。逐项如下。

### 1.1 站得住、继续保留的判断

- **单一品牌色锚点策略**：对。iA 蓝光标 / Caret 金光标 / Bear 红 / Reflect 紫都验证了「一个颜色即品牌」（签名素材库「品牌色光标」；文献「一处放胆」——Anthropic Frontend Design skill）。方向对，**但落点要改**（见 1.2）。
- **等宽/衬线分治（起草 vs 阅读）**：对，且对我们这类用户尤其成立。文献根据充分——iA《In Search of the Perfect Writing Font》：等宽体「暗示这是 work in progress」，比例衬线「暗示 This is as good as done」。对**开发者、英文优先**的定位（PRD §3，明确排除中文创作者），等宽默认是加分而非模仿。
- **暖纸底 + 暖墨**：方向对。文献（iA《Responsive Typography》、护眼配色研究）支持暖 off-white + 暖近黑，避免纯黑纯白炫光。**但不能当 identity**（见 1.2）。
- **强调色稀缺纪律**：对。60-30-10 文献 + 文献「accent 意味着『在此操作』，保持它稀缺」。方向对，落点要改。
- **anti-conceal 行内混合渲染 = 编辑主形态**：对，这是唯一能在 MiaoYan 主场赢它的形态（对抗式审查第 6 条；PRD §5.1 已把它列为 M2 目标）。
- **SF Pro chrome + 系统集成（MarkEdit 路线）**：对，是相对 Electron 的结构性护城河（ui-and-design §2）。

### 1.2 太 generic / 与谁重合（据 critique，诚实）

| 提议元素 | 判定 | 与谁重合 / 为什么弱 | 出处 |
|---|---|---|---|
| 暖纸白 #FBFAF6 作 **identity** | 偏通用需强化 | 撞 iA / Apostrophe / Paper / Byword / Craft——「纸面暖白」是整个极简写作阵营的默认底色；且 #FBFAF6 极接近纯白，多数人根本感知不到那点暖，**既通用又隐形** | 对抗式审查第 1 条 |
| 赤陶红撒在 **光标/链接/焦点/勾选** 当通用强调色 | 偏通用需强化 | ①「红=Bear」在 Markdown 语境已被占；②红在 UI 里天然是错误/删除语义；③会和 macOS 系统蓝（选区/控件）打架，破坏我们最想要的系统感 | 对抗式审查第 2 条 |
| **默认 duospace/等宽** 作 identity | 太像别人需改（部分采纳，见下） | 「duospace/Duo」基本是 iA 造的词，重合≈100%；`docs/` 记 iWriter Pro 为「廉价版 iA、被指模仿缺原创性」的前车之鉴 | 对抗式审查第 3 条 |
| **预览态 New York** 且隐含「选了衬线≈排版做完了」 | 偏通用需强化 | NY 是系统衬线，本身零辨识度；Craft 的出版级口碑来自**校准**（字距/行高/层级），不是「选了个衬线」 | 对抗式审查第 4 条 |
| **三栏**作默认/identity | 偏通用需强化 | 直接等同 Bear/Ulysses/MiaoYan/Obsidian，「三栏=标准=不特别」；中栏「文件列表」是最没记忆点的部分，尤其撞 MiaoYan | 对抗式审查第 5 条 |
| **⌘\ 分屏预览**作招牌 | 太像别人需改 | ⌘\ 分屏是 MiaoYan 的招牌原话；且分屏范式「正在过时」，押招牌=押正在死的交互，还押在对手已占的键位上 | 对抗式审查第 6 条 |
| 标记符「**淡化保留**」 | 偏通用需强化 | 是好 pattern 里最弱的一档（只追平 iA）；Bear「选中显形」、anti-conceal「只还原光标行」都是进阶版 | 对抗式审查第 7 条 |
| **整体组合观感** | 太像别人需改 | 四件叠起来≈「把 iA 的蓝换成红 + 文库侧栏换成三栏」＝iA/Bear/MiaoYan 三家拼贴，**缺一个真正属于自己的记忆点** | 对抗式审查第 8 条 |

### 1.3 两处我**不完全采纳** critique，并说明依据（请 Evan 复核这两个判断）

1. **字体：保留 duospace 默认，不改比例中文字体。** 对抗式审查第 3 条建议「默认改中文友好比例字体」，但那条建议的前提是追中文创作者差异化——而 PRD §3 已**明确把中文公众号排版者划出 MVP**、UI 英文优先、主用户是写 README/`CLAUDE.md` 的开发者。对开发者+英文优先，等宽/duospace 是母语审美（代码、终端、配置文件都是等宽），文献根据也在（iA 起草→定稿心理学）。所以**采纳「不能靠等宽皮建立 identity」这半句，拒绝「换成比例中文字体」那半句**——identity 改由 §3 的签名承载，中文混排降级为「加分项」而非身份（§3.8）。
2. **强调色：赤陶红收敛成「rubric（红批）」，但光标仍用赤陶红。** 对抗式审查第 2 条建议「光标/焦点走系统蓝」。我采纳它「把红从通用强调色收敛成 rubric、chrome 焦点/选区回归系统」的主张，但**保留赤陶红光标**——因为文献「一处放胆、让签名元素成为一屏可识别的那一个」（Anthropic Frontend Design skill）要求一个单屏记忆点，而「光标 + 光标行标记符都用赤陶红＝抄写员的红笔」是一个**统一概念**，比「红光标 + 其余中性」更有性格、更贴 Colophon（刻印/手抄本）这个自家世界。冲突用「稀缺化」化解（§3.1）：全强度红只出现在**光标 + 光标所在行**，其余标记符是安静的墨灰。

**一句话自评**：单品都对，缺的是**一个只属于我们、且从调研里长出来的招牌**。本文把它定为 **rubric 红批排版系统**（§3.1），并用 anti-conceal 承载、用校准排版托底。

## 2. 保留的简洁基线（哪些不动）

以下已在 [ui-and-design.md](./ui-and-design.md) 锁定、且被 critique 判为「对」，本文**不动**：

- **三条设计红线**：内容层永不套玻璃；优先系统标准组件；克制即差异化（ui-and-design §0）。
- **首屏 = 单栏纸面**，三栏是可逐级折叠的「管理态」，写作态一键回单栏（§4.1、§7.1）。**三栏不作 identity**，但作为管理形态保留。
- **无常驻工具栏**：格式操作交给快捷键 + 选中浮层 + 命令面板 ⇧⌘P（§4.1、§7.2）。
- **chrome 全用 SF Pro + SF Symbols + 语义色**，正文层才用 token（§2、§5）。
- **深/浅两套精调主题为一等公民**，跟随系统自动切换（§5.1）。
- **性能即观感**：近即时冷启、零延迟打字、大文件流畅滚动是显性验收项（§2）。
- **⌘\ 分屏保留为「按需逃生舱」**（对照/导出预览），只是**不再是招牌**——招牌让位给 anti-conceal（§7.6；对抗式审查第 6 条）。
- **入口双件套**：omnibar「搜索即新建」+ 命令面板（§7.2）——正好替换掉「三栏中那条最通用的文件列表」（对抗式审查第 5 条）。
- **色彩/间距 token 化**、无障碍硬底线、Liquid Glass 策略（§3、§5、§6）全部不动。

> 结论：简洁基线已经很扎实，本次迭代**只做加法中的减法**——不加面板、不加 chrome，只把「已有的克制」里注入一个有出处的招牌 + 几处开发者高频顺手。

## 3. 签名特色清单（8 条核心 + 3 条延伸）

**遴选标准**：①有出处（产品或文献）；②克制、不加常驻 chrome；③从我们自家世界（刻印/手抄本 + 开发者）长出来；④与竞品拉开距离。按「最值得投」排序。

### 3.1 【招牌 · 第一优先】Rubric 红批标记符系统（赤陶红光标 + 光标行红批）

- **具体做法**：把 Markdown 结构标记符（`#` `-` `>` `*` `` ` `` `[]()` 等）当**排版特征**处理：
  - 非光标行的标记符 → **墨色 35% 不透明**的安静淡化（灰化，不喧宾夺主）；
  - 光标所在行（anti-conceal 还原）的标记符 → **赤陶红 rubric 全强度**——像抄写员用红笔在你正在写的那一行做记号；
  - **光标本身 = 一根发丝级赤陶红竖条**，呼吸式柔和 blink 曲线。
  - 红色**只**落在「结构性 markup + 光标 + 离散确认标记（勾选框打勾的一次 flash）」，**绝不**用于 H1/H2、分节线、装饰分隔、hover 填充。
- **出处**：对抗式审查第 2 条（把签名素材库「品牌色锚点」#13 与「语法标记淡化」#10 合成一件事——iA 把标记淡成灰、Bear 直接藏，**没人把标记做成 rubrication**）；文献「rubric＝中世纪手抄本给标题/首字母用的红」「distinctiveness 要从产品自家世界（材料/术语/器物）里挖」（Anthropic Frontend Design skill）——Colophon 本身就是印刷术的尾标，rubric 是手抄本术语，二者同源；标记符淡化 30–40% 见文献（Bear、iA）。
- **为什么差异化**：这是**目前无人占用**的组合——iA 等宽灰标记、Bear 藏标记、MiaoYan 分屏无渲染，都没有「红批标记符」。它把「品牌色」「语法淡化」「刻印命名」三件事收成**一个概念**，回答了「缺一个属于自己的记忆点」（对抗式审查第 8 条）。
- **为什么克制不越界**：全强度红**自我稀缺**——只在光标 + 光标行出现，阅读/预览态无标记＝零红，满足 60-30-10 稀缺律（文献「accent 保持稀缺」）；离线标记走墨灰（文献「标记 30–40% 墨色、勿用 accent」）——两条文献看似冲突，用「离线墨灰 / 光标行红批」的**分区**同时满足。chrome 焦点/选区仍走系统色，不撞 macOS、不撞红=错误语义（对抗式审查第 2 条）。

### 3.2 【招牌 · 第一优先】anti-conceal 行内混合渲染（编辑主形态）

- **具体做法**：全文保持渲染态，**只把光标所在行/选区还原为源码**（「编辑哪行哪行变源码」），只渲染可视区域；光标移动只重排当前行，**绝不**整篇重排。源码/实时/阅读三态一键切换。
- **出处**：签名素材库「anti-conceal」（render-markdown.nvim；反例 markview.nvim「光标一动整片渲染就消失」打断心流）；文献「最不刺眼的渲染＝视觉状态变化最小的那个」（Bear 隐形 Markdown、你们 `docs/12`）；PRD §5.1 已列为 M2。
- **为什么差异化**：这正是打 MiaoYan 的点——它明确放弃 WYSIWYG 只能做分屏，我们做成 anti-conceal 就**在它主场赢它**（对抗式审查第 6 条），而不是跟它做同一个分屏。
- **为什么克制不越界**：视觉状态变化最小化，本身就是「克制」的极致；分屏降级为按需逃生舱，不与之竞争。

### 3.3 【招牌 · 第一优先】排版三态系统：duospace 起草 → New York 定稿（校准，非选字体）

- **具体做法**：三种字体绑定到**三种状态**，而非做成随手切的主题开关：
  - **chrome** = SF Pro（工具栏/侧栏/列表/状态栏/菜单）；
  - **源码/编辑画布** = duospace（起草态）；
  - **阅读/预览（WKWebView）** = New York 衬线（定稿态），用其光学尺寸（Small 作正文、Large/XL 作标题）。
  - 关键是**校准**而非「选了衬线就完事」：版心行宽、行高、标题字号阶梯全部按 §4 数值落地。
- **出处**：文献 iA《In Search of the Perfect Writing Font》（等宽=起草、比例=定稿，切换字体＝切换心理状态）、Apple New York（「SF 的伴侣衬线」，可变光学尺寸，专为长文阅读）、文献「三种字体各司其职：mono 起草 / serif 阅读 / sans 做 chrome」；「差异化在校准不在选字体」（对抗式审查第 4 条）。
- **为什么差异化**：把「字体绑定到编辑 vs 预览状态」让**模式切换本身讲出 draft→done 的叙事**，而不是暴露成一个随机主题开关；再叠加校准，就不是「又一个用系统衬线的 app」。
- **为什么克制不越界**：只给 Notion 式 3 档正文（Duospace / Serif / Sans），进阶参数（行宽/行距/字距）埋进设置深处（文献「一套无可挑剔的默认 + 至多三个都成立的备选」——iA、Bear Sans、Notion）。**不做字体下拉列表**。

### 3.4 标题层级视觉分级（字号阶梯 + 可选克制色阶）

- **具体做法**：六级标题用**字号阶梯**拉开清晰层级（H1 显著大于 H2 大于 H3……），可叠加**极克制的墨色色阶**（越高级越深）辅助；代码块加背景色 + 语言标签。
- **出处**：签名素材库「标题层级视觉化」（render-markdown.nvim 色阶方案被点名可直接参考）；反例 Zed 预览 h1/h2/h3 字号几乎一样、层级不可见（`docs/12` §五-B-9）。
- **为什么差异化**：开发者向编辑器普遍不重视排版美学（Zed 层级不可见是典型），这正是「好看得不像开发者工具」的空档。
- **为什么克制不越界**：层级**先靠字号**，色阶是可选辅助且**只用墨色深浅、绝不用 rubric 红**（红是 §3.1 的专属，headings 用红会破坏稀缺——文献 60-30-10 硬规则）。

### 3.5 开发者高频微交互三件套（智能续行 + 粘贴 URL 成链接 + 图片零摩擦落盘）

- **具体做法**：
  - **列表智能续行**：回车自动续列表项、Tab/退格调缩进层级、有序编号自动修复、空项回车自动清标记；
  - **选中文字粘贴 URL → 自动 `[文字](url)`**（原生 NSPasteboard 做得比 Electron 顺）；
  - **拖拽/粘贴图片自动落盘**到可配置相对目录并插入引用（可选压缩、显示进度）。
- **出处**：签名素材库「列表智能续行」（Markdown All in One、Zed、Sublime MarkdownEditing）、「粘贴 URL 成链接」（VS Code 开发者基线）、「图片零摩擦落盘」（VS Code、MWeb、doocs/md）。
- **为什么差异化**：这些是开发者的**隐性标配**，通用写作类编辑器常缺；缺则立即被感知，做顺了口碑立现——是「开发者的编辑器」最便宜的证明。
- **为什么克制不越界**：**零新增 chrome**，全部藏在输入行为里，触发才有、静止无痕。

### 3.6 QuickLook 预览 + 原生系统集成

- **具体做法**：提供 QuickLook 插件，让 Finder 里空格键直接渲染 `.md`；配合 Writing Tools、系统拼写、Spotlight 索引正文。
- **出处**：签名素材库「QuickLook 预览」（iWriter Pro）；文献「macOS 上深度原生集成是差异化而非同质化的根源，是 Electron 竞品做不到的」；ui-and-design §2 系统集成清单。
- **为什么差异化**：脱离 app 也能看到我们的排版，是 Electron 竞品（Obsidian「原生集成弱」）做不到的原生细节。
- **为什么克制不越界**：发生在 OS 层，app 内**零 chrome 成本**。

### 3.7 安静界面：选中浮层 + 悬停浮现（无工具栏）

- **具体做法**：格式化浮条**只在选中文本时**出现，否则完全隐身；块级能力（拖拽手柄/`+`）**hover 才浮现**，静止时纯纸面。
- **出处**：签名素材库「选中浮层工具条」（MarkPad、Notion）、「能力藏在悬停里」（Notion「安静界面」教科书）。
- **为什么差异化**：免去常驻工具栏又保留可发现性，与我们「无工具栏 + 命令面板」方向严丝合缝。
- **为什么克制不越界**：静止＝纯净纸面，能力按需浮现——这正是「简洁但可发现」的范式，不是加法。

### 3.8 非侵入 monospace 状态行（呼应刻印命名）

- **具体做法**：底部一条**可关、可自定义**的 monospace 信息条：字数/阅读时长/（可选）本次会话字数与码字速度；用等宽体呼应「colophon（版权尾标）」的印刷术出身。
- **出处**：签名素材库「非侵入信息挂载」（Ulysses 附件栏、WriteMonkey 可自定义底部条、doocs/md 字数+阅读时长）、「会话统计」（ghostwriter）；文献「从自家 vernacular 取细节：monospace 状态/字数行、印刷母题」（Anthropic Frontend Design skill）。
- **为什么差异化**：把 status line 做成一个小小的「colophon」，是命名到界面的呼应，别人不会这么想。
- **为什么克制不越界**：挂在纸面之外、默认低调、可一键关；写作态不被计数打扰、需要时一瞥即得。

### 3.9 延伸签名（对齐但延后 / 加分，不进 MVP 核心）

以下三条方向对、有出处，但更重或非当前人群刚需，列为**路线图签名**，不进 MVP 首屏定调：

- **代码块语言注入**（tree-sitter）：代码 fence 内获得该语言完整高亮/补全/检查——面向开发者最有说服力的差异化（签名素材库；JetBrains、Emacs markdown-mode）。**V1+**。
- **中西文混排自动空格 / 中文标点行高优化**：解析或保存层自动排版（签名素材库；MiaoYan、Lute、SiYuan、语雀）。定位为**加分项而非 identity**（PRD §3 中文非 MVP），须提供 proseWrap `preserve/never` 避免多余空格。**V1 可选**。
- **AI 文本标注（Authorship）**：标注哪些字来自 AI，信息存文末独立块、导出自动剥离（签名素材库；iA Authorship 已开源为规范）。与 Route B 天然契合，「能标注 AI 写了哪些字的开源编辑器」是清晰传播点。**Route B 阶段**。

## 4. 修订后的具体规格

> 以下数值是 mockup 的**起点**，落地时逐像素微调，深/浅/纸三态都要过（ui-and-design §5、§6）。所有正文色走 token，chrome 走系统语义色。

### 4.1 字体（验证 duospace 默认，依据见 §1.3）

| 角色 | 字体 | 依据 |
|---|---|---|
| chrome（工具栏/侧栏/列表/状态栏/菜单） | **SF Pro**（系统） | ui-and-design §2；文献「sans 做 chrome 的中性主力」 |
| 源码/编辑画布（默认起草态） | **duospace**：首发用 **iA Writer Duo S**（SIL OFL 开源，可直接打包）或其底 **IBM Plex Mono**；后续可评估自研 | iA 起草→定稿心理学；开发者母语审美；PRD §3 英文优先 |
| 阅读/预览（WKWebView，定稿态） | **New York**（系统衬线，用光学尺寸 Small/Large/XL） | Apple New York 长文阅读；文献 draft→done |
| CJK 回退 | 正文/预览 CJK 走 **PingFang SC**（或 Source Han），配自动中西文间距 | 签名素材库中文混排；作加分项非 identity |
| 正文档位（给用户） | 仅 3 档：**Duospace / Serif / Sans**（Notion 式） | 文献「至多三个都成立的备选，勿做字体列表」 |

- **默认字体决定：编辑画布 = duospace（iA Writer Duo S 为首发候选），预览 = New York。** 采纳「不靠等宽皮立 identity」，identity 交给 §3.1 rubric；拒绝「换比例中文字体」（依据 §1.3）。

### 4.2 强调色（验证 terracotta，重定义角色）

**决定：验证赤陶红 #B23A28 作唯一强调色，但把角色从「通用强调色」重定义为「rubric（红批）」**——只落在光标 + 光标行标记符 + 离散确认标记 + 链接下划线；chrome 焦点/控件/选区回归系统色（依据 §1.3、对抗式审查第 2 条）。

| Token | 浅色（light，默认） | 纸感（paper/sepia，一等公民） | 深色（dark） |
|---|---|---|---|
| 画布 `canvas.bg` | `#FBFAF6` | `#F4EDDD`（暖奶油，让暖真的被感知） | `#1C1B19`（柔炭，非纯黑） |
| 正文墨 `ink.body` | `#1F1B18`（暖近黑，勿纯黑） | `#2B2620` | `#E7E3DA`（暖 off-white，勿纯白） |
| rubric 强调 `accent` | `#B23A28` | `#A8402E`（在奶油上略压深） | `#D2674F`（提亮以保对比） |
| 离线标记符 `marker.idle` | `ink.body @ 35%` | `ink.body @ 35%` | `ink.body @ 40%` |
| 光标行标记 `marker.active` | `accent` 全强度 | `accent` 全强度 | `accent` 全强度 |
| 选区 `selection` | 暖去饱和 wash（`accent @ 12–15%`，**非系统蓝**） | `accent @ 12%` | `accent @ 18%` |
| 链接 | 墨色文字 + `accent` 细下划线（红只落在「rule」上） | 同左 | 同左 |
| 分隔线 `separator` | `#E5E1D8`，0.5px @2x 发丝线 | 近似暖灰 | 暖炭灰 |
| chrome 焦点/控件 | **系统 accent**（原生） | 系统 accent | 系统 accent |

- **画布决定**：`#FBFAF6` 保留为 **light** 值，但**降级为三态之一、不作 identity**（对抗式审查第 1 条）；另设**明显更暖的 paper `#F4EDDD`** 让「暖」可感知（可设为默认以贴品牌）。深色用柔炭 `#1C1B19`，配 Tahoe 非纯黑暗面。
- **对比校验**：`ink.body` 对 `canvas.bg` 必须 ≥ WCAG AA 4.5:1（三态都验）；rubric 红不得成为唯一信息载体（色盲友好——标记符同时有形状）。

### 4.3 字号阶梯 / 版心 / 行高（依据 Butterick + iA）

- **正文字号**：编辑画布 duospace **16px**（等宽视觉偏大）；预览 New York **18px**（文献「正文 15–25px、iA 基准 Georgia 16px」）。可在设置调，禁写死。
- **行高**：编辑 **1.55**、预览 **1.6**（文献「120–145%，140% 是好基准」）。空间紧张时**先缩外边距，再缩行高**（文献「gutter 与 leading 是功能性阅读辅助，不是可压的 padding」）。
- **版心行宽（measure）**：按**字符数**算，不按像素——编辑 **~68ch**、预览 **~65ch**，居中，留真实左右边距（文献「45–90 字符/行，短行更舒适」）。字号变化时按字符数重算宽度。
- **左 gutter**：保留真实左槽，把 `#` `-` `>` 标记符**悬挂进左 gutter**，正文保持齐左（文献光学对齐 / hanging punctuation）。
- **标题字号阶梯**（预览，New York，比例 ~1.2–1.25）：

| 级 | 字号 | 说明 |
|---|---|---|
| H1 | ~30–32px | 光学尺寸 Large/Display |
| H2 | ~26px | 与 H1、H3 必须一眼可辨（反 Zed） |
| H3 | ~22px | |
| H4 | ~19px | |
| H5 | ~17px | |
| H6 | ~16px | 可选小型大写 / 最深墨色阶 |

### 4.4 签名细节落地参数

- **光标**：赤陶红发丝竖条（约 1.5–2px @2x），呼吸式 blink（缓入缓出，非硬闪）；打字时可暂停 blink。
- **离线/光标行标记**：离线 `marker.idle`（墨 35%）、光标行 `marker.active`（accent 全强度）；切换只重排当前行（anti-conceal），**禁整篇重排**。
- **勾选框打勾**：完成瞬间 rubric 红 **flash 一次**再落定，呼应 macOS 右键菜单选中前「blink accent」的确认微动效（文献 Rauno Sirén）。
- **动效纪律**：动效只留给**空间变化**（侧栏展开、⌘\ 分屏打开）；**高频键盘动作**（切预览、新建、切焦点）**不加动画**；每个过渡可中途打断（文献 Rauno Sirén「键盘输入 less visceral、少动效」「过渡须可打断」；ui-and-design §4.5）。
- **发丝分隔线**：三栏分隔用 0.5px @2x，不用 1px 粗线（文献光学对齐「0.08–0.15pt 是最细可靠可见分隔」）。
- **专注/打字机模式**：句/段焦点淡化（淡成**暖灰、绝不用 accent**）+ 打字机当前行居中，**均默认关**、各一键切换；编辑修订时能无摩擦退出（文献 iA Focus Mode 自身告诫「修订时关掉 Focus」）。

## 5. 给 mockup 的修改清单（逐条可执行）

按此改图，从上到下即可：

1. **画布**：默认底色改为 **paper `#F4EDDD`**（或保留 light `#FBFAF6` 但**务必**并排放一版 `#F4EDDD` 对比，选能真感知到暖的那版）；正文墨改 `#1F1B18`（勿纯黑）。出三态：light / paper / dark（dark 用 `#1C1B19` + `#E7E3DA`）。
2. **强调色收敛**：把当前撒在链接/焦点/勾选上的红**全部撤掉**，只保留在：①**光标**（赤陶红发丝竖条）；②**光标所在行的 Markdown 标记符**（全强度 `#B23A28`）；③勾选框打勾的一次 flash；④链接**下划线**（文字仍墨色）。chrome 的焦点环/选中/按钮改回**系统 accent**。
3. **标记符两态**：非光标行标记符画成**墨色 35% 灰淡**；光标行标记符画成**赤陶红全强度**——这一对比是本图的招牌，务必让它一眼可见。
4. **字体三角色**：chrome 用 SF Pro；编辑画布用 **duospace（iA Writer Duo S / IBM Plex Mono）**；预览面板用 **New York**。同一张图若含编辑+预览，务必让两侧字体不同以讲出 draft→done。
5. **版心**：编辑区文本列限宽到 **~68ch**（预览 ~65ch），**居中**，左右留真实边距；正文字号 16px（编辑）/18px（预览），行高 1.55/1.6。
6. **左 gutter 悬挂**：把 `#`、`-`、`>` 等标记符**挂到正文左边界之外**（悬进 gutter），让正文首字齐左成一条竖线。
7. **标题阶梯**：按 §4.3 字号画 H1–H3，**必须一眼分得出层级**（对照反例：不要画成 Zed 那样三级几乎等大）；标题**不得**用红，层级靠字号（+ 可选墨色深浅）。
8. **三栏 → 单栏优先**：主图画**单栏纸面**（写作态）；三栏只作为一张「管理态」附图，且中栏画成 **omnibar（搜索即新建）+ 列表**、不是普通文件树。
9. **无工具栏**：不画常驻格式工具栏；画一个**选中文本才出现**的浮条示意 + 顶部极简（仅必要窗口控件）。
10. **状态行**：底部画一条 **monospace** 细信息条（字数 · 阅读时长），低调、可关的观感。
11. **分隔线**：三栏/区块分隔用 **0.5px 发丝线**（`#E5E1D8`），不要粗线。
12. **分屏**：若要展示 ⌘\ 分屏，标注它是「按需逃生舱」，**不要**把它画成默认主形态——默认主形态是单栏 + anti-conceal 行内渲染。
13. **一张「anti-conceal」示意**：画一行「光标停在此行 → 显示源码（含红批标记）」，其上下行「保持渲染态（标题变大、粗体变粗、标记淡化）」，直观呈现编辑主形态。
14. **自检**：每屏问一句——「这看起来像 **Colophon**，还是像任何一个极简 app？」（文献反 blanding）。招牌（rubric 红批 + duospace→NY + 校准版心）至少有一处能在**单张截图**里认出来。
